PHASE 3 — Medium: client-side service layer                           [MEDIUM]
--------------------------------------------------------------------------------

All admin pages pass fetch() inline inside queryFn. Per CLAUDE.md, pages and
hooks should not call fetch directly — a services/ layer wraps the API calls.

  Create services/ directory with one file per domain:

  services/
    auth.service.ts             logout()
    admin-usuarios.service.ts   listarUsuarios(), criarUsuario()
    admin-tenants.service.ts    listarTenants()
    admin-rondas.service.ts     listarRondas()
    admin-patrimonio.service.ts listarChamados()
    admin-dashboard.service.ts  buscarMetricas()
    agendamentos.service.ts     listar(), criar(), atualizarStatus()
    trilogo.service.ts          buscarEmpresas(), buscarAssets()

  Pattern for each service function:
    export async function listarUsuarios(): Promise<Usuario[]> {
      const res = await fetch('/api/admin/usuarios')
      if (!res.ok) throw new Error()
      return (await res.json()).data ?? []
    }

  Then in pages/hooks:
    queryFn: () => adminUsuariosService.listar()   ← clean, no inline fetch

  Files to update after service layer exists:
    app/admin/usuarios/page.tsx
    app/admin/tenants/page.tsx

BOUNDARY RULES (from CLAUDE.md — never break these)
--------------------------------------------------------------------------------

  route.ts        receive req → verify auth → call service → return response
  modules/        all business logic + Prisma queries
  components/     dumb UI — props in, events out, NO fetch
  hooks/          state + client-side calls — pages consume hooks
  services/       client-side fetch wrappers targeting /api/* routes
  lib/            shared server utilities (db, jwt, api-response)

  DO NOT:
    - call fetch() inside a component
    - call fetch() inside a page (use a hook or service + useQuery)
    - write Prisma queries in route.ts
    - accept criadoPorId/tenantId/role from request body
    - skip tenant isolation filters on Prisma queries
    - use any / @ts-ignore
    - add business logic to route.ts
